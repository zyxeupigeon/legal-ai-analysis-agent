# P2.3.4 证据相关性审计与冲突处理

## 目标

修复P2.3.3真实报告中出现的“有引用但不支持具体主张”、高等级来源漏检、备案降级语病，以及API、MCP、Skill混合判断问题。继续保持单用户、本地运行、免费测试级搜索和DeepSeek默认模型，不建库、不部署、不训练。

## 证据相关性审计

报告草稿生成并通过URL存在性检查后，系统为每条摘要、每个实际内容章节和每条洞察建立审计目标。审计器只能使用本轮已读取证据，逐项返回支持、部分支持或不支持，并列出真正支持目标全部重要事实的URL。

仅出现产品名、企业名或相邻概念不算支持。包含多个重要事实的段落，候选来源合计必须覆盖全部事实才能通过。未通过时允许模型在原证据范围内重写一次；再次审计仍未通过则停止，不生成Word。

## 检索优先级

科研机构、政府监管和官方开放平台查询置于一般企业、价格、媒体和客户查询之前，避免固定证据数量上限截掉高等级来源。每组查询限制结果数量，兼顾覆盖与模型上下文长度。

## 备案与冲突处理

没有监管来源时，包含“首批通过备案”等内容的整句改写为企业归因表述，并说明未取得监管公开名单直接对应记录，不再在原句中插入碎片。发现“历经若干年研发”和“某年成立联合实验室”等不同时间口径时，记录两种口径及可能边界，不直接认定矛盾，也不相互替代。

## 技术入口分层

身份生态检索分别查询API、MCP、插件、连接器和Skill。官方出现Skill接入只确认Skill线索；API不能推定MCP，插件或连接器也不能相互替代。每项仍需绑定对应公开来源。

## 阶段边界

本阶段仍只生成本地Word测试稿，免费检索不承诺正式报告所需的覆盖率和稳定性。不得把测试稿作为法律意见、审计、尽调或投资意见；不建库、不部署、不训练、不开放多用户。
