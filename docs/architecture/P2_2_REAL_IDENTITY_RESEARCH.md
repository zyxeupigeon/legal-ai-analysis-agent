# P2.2 真实身份与公开信息检索

## 目标

P2.2把P2.1的确定性身份闸门替换为真实Agent检索，同时保留原有澄清流程和任务状态机。输入仍只有产品名称。

## 执行顺序

1. 根据环境配置选择模型适配器与公开搜索适配器；默认使用DeepSeek和Tavily，也保留OpenAI原生检索。
2. 外部搜索模式先执行两组身份查询，再把实际搜索结果交给模型核验唯一产品身份、运营主体与法律AI用途；模型只能引用搜索结果中出现的网址。
3. 若有歧义，最多给出三个候选并进入“等待产品确认”；此时禁止生态扩展。
4. 用户选择候选或填写确切全称后，再执行一次公开核验。用户确认不替代事实证据。
5. 仅在身份闸门通过后，再执行运营主体生态与MCP两组查询，识别同一运营主体的其他AI产品以及API、MCP、模型平台、知识库、Agent、插件等线索。
6. 输出结构化结果、公开来源、限制和阶段状态；在正式报告生成前停止。

## 可信边界

- 来源优先级：政府/监管、产品官网和官方文档、官方条款、运营主体官网、可靠行业与媒体来源。
- 不因名称相似、网页跳转、搜索摘要或模型记忆合并主体与产品。
- MCP只有在官方明确命名，或存在可核验服务端点、配置或使用文档时才能确认。
- 名称或证据不足属于歧义，不属于越界；越界必须有公开证据表明对象不是法律AI产品。
- 公开检索异常、超时、上游结构错误时不产生身份结论，也不创建伪结果。

## 权限与数据

- 允许无需登录的公开网页检索，无需逐次征求同意。
- 不允许登录、付费、受限内容或电脑操作；这些能力本阶段没有实现。
- 请求只发送产品名称和必要的候选运营主体提示。
- OpenAI Responses请求固定 `store=false`；DeepSeek与兼容接口只发送产品名称、搜索证据和必要候选提示。本地任务只存内存，重启即清空。
- 测试提供方必须显式设为 `fixture`，不得在真实提供方失败时静默回退。

## 适配边界

- 身份工作流只依赖统一的“结构化模型”和“公开搜索”协议；新增供应商时不修改状态机、澄清流程或页面业务规则。
- `deepseek`是首个外部搜索模型适配器；`compatible`可接入支持OpenAI Chat Completions与JSON模式的服务。
- 当前外部搜索适配器为Tavily。以后可增加其他搜索服务，但必须继续执行URL白名单、来源分层和失败即停止规则。
- 模型和搜索密钥只从服务端环境变量读取，绝不发送给浏览器或提交到Git。

## 完成标准

- 明确产品：身份、主体、法律AI范围、来源和生态线索结构均可返回。
- 歧义产品：停止并等待用户确认，关联生态为空。
- 越界产品：任务终止且不生成后续内容。
- 缺少密钥、网络或上游异常：显示可理解错误，不保存伪结论。
- 自动化测试与页面构建通过；真实付费冒烟测试仅在本地存在API密钥时执行。
