# P2.3.2 证据覆盖与报告质量修复

## 目标

在P2.3.1本地报告闭环之上，修复身份结论和报告来源脱节、生态项确认状态过强、正文长网址难以追溯以及弱证据支撑强结论的问题。

## 证据流

1. 身份闸门保留产品、运营主体、法律AI属性和生态项对应的来源。
2. 报告研究继续执行五组公开检索，并与身份阶段来源按规范化URL去重。
3. 正文章节和洞察只能引用上述两类已取得来源。
4. 产品生态表逐项读取自身 `source_urls`；确认项没有有效来源映射时，报告中自动降级为公开线索。
5. 来源清单记录来源名称、证据等级、访问日期以及是否从身份阶段继承。

## 证据等级

- 政府或监管公开记录：用于支持备案、登记或监管公开事实。
- 官方原始资料：用于证明企业或产品公开披露，不自动证明效果、规模或壁垒。
- 第三方公开资料：用于外部交叉验证，仍需核对统计口径和原始出处。
- 其他公开资料：证据能力有限，只能支撑与页面直接对应的有限陈述。

## 结论保护

模型提示禁止把备案、联合研发、产品上线、数据规模自述和价格梯度直接写成壁垒、成熟变现、市场认可或付费意愿。程序对常见过强表述再次执行确定性降级，避免单次模型偏差直接进入Word。

## Word输出

- 报告摘要、各章节、洞察和生态表使用 `[序号]` 映射来源。
- 来源清单显示访问日期和证据等级，不在正文堆叠长网址。
- 生态类型、核验状态使用中文；API、MCP、插件、连接器和Skill继续分层。
- 文件仍明确标为P2.3.2本地测试稿，不得作为正式对外报告。

## 阶段边界

本阶段不建立数据库、不部署、不做多用户、不训练、不接入付费搜索，也不把测试级免费搜索升级为正式报告证据服务。
