# P2.3.3 主张—证据绑定与逻辑校验

## 目标

修复P2.3.2真实报告测试中发现的正文无逐段引用、来源类型混标和无充分证据强推断问题。保持单用户、本地、免费测试级搜索和DeepSeek默认模型，不引入数据库、部署、多用户、训练或付费服务。

## 主张—证据契约

- 报告摘要必须至少绑定一个本轮有效来源。
- 五个主体章节中，只要存在实际分析内容，就必须至少绑定一个本轮有效来源；固定的“证据不足”占位段除外。
- 每条洞察必须至少绑定一个本轮有效来源。
- URL必须来自身份阶段证据或本轮报告检索结果。模型漏引、空引或使用未知URL时自动修复一次；修复后仍不合格则停止生成Word。
- Word继续用来源编号展示正文与来源清单的对应关系。

## 来源分类

- 政府或监管公开记录：用于直接核验备案、登记等监管事实。
- 官方原始资料：企业官网、官方文档等企业一手披露。
- 应用商店或分发平台资料：只证明平台页面所展示的产品信息。
- 科研机构公开资料：科研院所官网披露的合作或项目记录。
- 第三方及其他公开资料：按其来源属性单独展示，不升级为官方事实。

## 逻辑保护

- 定价或套餐只证明设置了收费渠道，不证明收入、成熟变现或付费意愿。
- 研发起点早于公司成立不自动构成矛盾，也不自动影响公信力。
- 备案强结论必须有政府或监管来源；仅有企业披露时改为归因表达并说明未取得监管名单直接对应记录。
- 上线、合作、备案、数据规模自述不直接推出壁垒、领先、市场认可或行业势能。

## 检索与文档

报告研究增加监管备案、算法记录和科研院所合作查询。仍只使用免密钥测试级公开搜索；搜索失败或无法取得可读证据时停止。来源清单从新页开始，避免标题和首条来源被前页内容割裂。

## 阶段边界

本阶段只生成本地Word测试稿。报告不得作为正式对外报告、法律意见、审计、尽调或投资意见；不建库、不部署、不训练、不开放多用户。
