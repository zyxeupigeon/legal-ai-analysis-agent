# P2.3.1 证据约束报告最小闭环

## 目标

在P2.2.2身份闸门通过后，继续使用已配置模型与公开搜索，生成可编辑的本地Word测试稿，验证“产品输入—身份核验—证据研究—报告草稿—Word下载”闭环。

## 执行顺序

1. 用户提交确切产品名称；歧义未消除时停止。
2. 身份闸门确认产品、运营主体和法律AI属性，并识别同企业相关AI产品、API与MCP线索。
3. 用户点击生成报告后，系统重新按报告维度检索公开信息。
4. 模型只依据任务卡片与本轮实际检索证据形成结构化草稿。
5. 系统删除不属于实际检索结果的引用；全部引用无效时拒绝生成。
6. 系统将草稿写入本机Word文件并提供下载。

## 报告结构

- 报告摘要
- 企业发展历程与核心驱动
- 企业经营情况
- 企业业务版块
- 企业行业势能
- 企业市场布局
- 洞察总结
- 研究边界
- 主要数据来源一览

五个主体章节必须存在且顺序固定。证据不足时保留标题、缩短内容并写明边界，不为填满结构而补造信息。

## 失败关闭

- 产品身份未确认：返回冲突状态，不启动报告研究。
- 模型或搜索未配置：返回未就绪状态。
- 搜索没有可读证据：停止任务，不使用模型记忆。
- 草稿没有引用实际来源：拒绝生成Word。
- Word写入失败：任务标记为失败，不提供虚假下载入口。

## 数据与权限边界

- 任务只存在进程内存；重启后清空。
- Word只保存到本机Git忽略目录 `artifacts/local`。
- 不建立数据库，不上传报告，不训练模型，不部署，不开放多用户。
- 免密钥搜索仍属于测试级组件，生成物必须标明测试稿，不作为正式对外报告。
