# Agent entry point

On the first user message of every new session, before answering or doing any other task, read PROJECT_AGENT_PROTOCOL.md in full and run its workspace preflight. Start the first reply with SESSION_PREFLIGHT_READY or SESSION_PREFLIGHT_BLOCKED. If blocked, explain the blocker and do not allocate a task workspace, research, or generate a report. Its protocol id is portable-agent-1.0.

Verify that the current absolute directory matches LEGAL_AI_PROJECT_ROOT when that variable is set. Run the protocol preflight, verify every capability needed by the request, and allow only low-risk no-restart automatic repairs. Before READY, run the one-use visual challenge in `scripts/session_preflight_gate.py`, inspect its PNG with the same direct image-view capability intended for final report pages, and obtain a capability receipt. Geometry-only or text-only inspection is not sufficient. Run `scripts/create_task_workspace.py --task-id <id> --session-gate READY --capability-receipt "<CAPABILITY_RECEIPT>"` only after declaring SESSION_PREFLIGHT_READY, then use only its absolute TASK_OUTPUT_DIR. Stop on any root mismatch. Do not assume web access, browser access, MCP availability, document tooling, or model capabilities.

Research scope is limited to free, public, no-login information for readers who have not used the target legal AI. Never register or log in to the target product, pay or recharge, invoke its API/MCP/Skills, upload files, operate product features, or claim measured accuracy or effectiveness. A PASS validates this project's research and document pipeline, not the target product.

Generate only the canonical `report.docx`, then use `scripts/render_report.py` so rendering failures and retries are recorded and no duplicate DOCX/PDF remains. Every complete report must also create `claim_evidence.json`, record and finalize `execution_trace.json`, and pass source binding plus repeating table-header validation. Build `process_optimization_report.md` from the finalized trace, then generate `report_diff.json`, `report_diff.md`, and the SHA-256-bound `report_manifest.json` before writing the final `run_summary.md`. In the final reply, state the absolute path and filename of `report.docx`, the optimization report, and the human-readable version diff.
